# 그룹 색상 필드 탐색 일반화 1차

**FIELD_LOCATOR_PARTIAL**. 읽기 전용 탐색기를 작성했고 기존 G1의 R2 후보 구간을 절대 offset 하드코딩 없이 재현했다. 그러나 독립적인 구성원 소유권 판단은 미완성이므로 **모든 결과의 `change_allowed`는 false**다. 모호한 상태에서 Stage B를 계획하거나 실기를 요청하지 않았다.

## 구현한 탐색 방식

[field_locator.py](field_locator.py)는 기존 Decoder를 수정하지 않고 다음 순서로 보존 데이터를 읽는다.

1. 그룹 후보 1개·선언 수 1·사각형 chain 후보 2개인지 확인한다. bbox·크기·contour 기록으로 각 후보를 구분한다. 순번은 이 Decode의 순번일 뿐 영속 ID가 아니다.
2. 각 chain의 원본 contour 범위가 파일 바이트와 정확히 일치하는지 확인한다. 사각형 후보·기록 4개·36바이트 stride·직전 count/kind와 유한·비퇴화 bbox를 확인한다. **색상 바이트 검색이나 가장 가까운 위치 선택을 사용하지 않는다.**
3. contour 기록의 끝에서 바로 다음 archive tag 후보를 읽는다. 이름이 기록된 경우 CPropertyExtend/schema 5를 요구한다. 짧은 class reference이면 본문 시작 후보만 계산하고 **참조 클래스는 UNKNOWN**으로 남긴다. null/객체/확장 참조 등 미지원 분기는 거부한다.
4. S1/S2 단독 표본의 이름 있는 property 본문을 대조해 색상 전 공통 prefix와 두 필드 사이 구간을 학습한다. 첫 차이와 두 번째 차이가 각각 통제된 색상의 4바이트 값인지 확인한다. 이번 학습 결과는 본문 상대 **120, 132**다. 이 수치를 코드 상수로 입력하지 않았다.
5. 후보 본문의 prefix·필드 사이 구조가 학습값과 일치하고, 두 4바이트 값이 같은 알려진 RGB0 팔레트 값인지 확인한다. 구성원 간 후보 범위 겹침이나 동일 bbox 등 혼동은 거부한다.

이것은 **통제된 스타일 본문 프로파일과 contour 끝에 기반한 후보 탐색**이지, 완성된 MFC/그룹 계층 Parser가 아니다. 프로파일에는 의미가 미확정인 바이트도 포함되므로 다른 스타일을 임의로 허용하지 않는다.

## 실제 기존 표본 결과

| 입력 | 탐색 결과 | 변경 허가 |
|---|---|---|
| S1/S2 단독 표본 | 학습 입력. 그룹 실행 대상으로는 거부 | false |
| U0 비그룹 2개 선택 | 거부 | false |
| G0-A / G0-B / G0-R / G1 | 두 사각형과 아래 후보 쌍 재현 | false |

| 과거 same-color 그룹 2개 | 이번 본문 프로파일과 달라 거부 | false |

G1 결과(0 기준·끝 제외):

| 후보 | contour 기록 | 후속 tag/본문 시작 후보 | 색상 쌍 |
|---|---|---|---|
| 작은 R1 | [630,774) | CPropertyExtend 이름 기록 → 795 | [915,919), [927,931), Navy Blue |
| 큰 R2 | [1375,1519) | `0x8008` class reference → 1521 | **[1641,1645), [1653,1657)**, Turquoise |

R2는 `본문 후보 1521 + 학습된 상대 위치 120/132`로 재현된다. 1641/1653은 탐색 코드에 없다. 절대 결과값 검사는 회귀 테스트에만 있다. R1/R2의 후보 필드 범위는 겹치지 않는다. bbox·크기·실제 읽힌 색상·tag·진단 사유는 [locator-result.json](locator-result.json)에 출력했다.

이 그룹 입력들은 **동일한 두 객체로 만든 한 계열의 반복·재생성·색상 대조 및 재Copy**다. 서로 독립적으로 만든 여러 그룹을 검증한 것으로 세지 않는다. 이미 성공한 특정 G1의 Native Paste 결과는 유효하지만 새 탐색기의 일반화 실기 성공으로 승계하지 않는다.

## VERIFIED로 판정하지 않은 이유

- `0x8008`의 Archive class/reference 표를 해석하지 않았다. 프로파일이 맞는다는 이유로 그 reference가 CPropertyExtend라고 확정하지 않았다.
- CPropertyExtend 본문 전체와 구성원 Serialize 종료 경계·소유 관계가 미확정이다.
- contour 범위·사각형·그룹 인식 일부는 기존 Decoder의 후보 판정에 의존한다.
- prefix·색상 쌍의 안정성은 현재 단독 두 표본에서 얻은 경험적 규칙이다. 생성 순서·스타일·좌표가 다른 독립 그룹에서는 확인하지 않았다.

따라서 **후보 위치를 구하는 데 진전은 있지만 새 그룹의 올바른 수정 대상을 안전하게 확정할 수는 없다.** 결과를 쓰기 API로 제공하지 않으며 패치 바이너리도 생성하지 않았다. 구성원별 실제 메모리 소유권이나 원본 객체 선택 기능을 해결한 것이 아니다.
