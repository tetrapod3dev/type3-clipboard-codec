# V2 이후 남은 차단 조건

V2는 지원 데이터의 발생 기록을 정리한 읽기 도구다. Geometry/Text occurrence를 서로 더하거나 count 후보와 맞추어 객체 수를 만들지 않는다. 두 목록은 같은 실제 객체의 문자 속성과 보조 Contour를 각각 포함할 수 있다.

- **정확한 선택 수**: preamble의 실제 producer 기록 순서와 count 의미가 미확정이다. 새 문자 intent의 구성원/최상위 범위 모호성을 해소할 독립 UI 기록이 필요하다.
- **객체 시작·끝과 map**: class descriptor와 object creation이 같지 않다. Archive 초기 상태 및 직접Serialize/WriteObject/SerializeClass의 구분, CParagraphe optional secondary CTxtPara와 this+148 후속 serializer 종료 계약이 필요하다. 003에서 차단된 분석을 재개하지 않았다.
- **소유권**: 같은 raw·문자 내용·색상은 객체 identity가 아니다. text record window와 전체 text 객체 body, 독립 선과 문자 보조 contour, Group/Member 연결은 UNKNOWN이다.
- **원본 작업 연결**: 영속 ID·원본 선택 적용·CAM 참조·Group 생성·이동·회전·Nesting·Paste·원본 대체는 이번 기능에 없다.
- **미지원 데이터**: 새 class/schema/property 구조, 다른 문자 인코딩/동적 slot layout은 현재 helper가 추출하지 못할 수 있다. 빈 text 목록은 문자가 없다는 증거가 아니다. V2의 발생 범위도 전체 Archive 유효 길이를 보장하지 않는다.
- **probe 범위**: 추가 Contour는 전체 SHA가 고정된 E1/F 두 입력에만 기존002 코드를 재사용한다. 그 밖의 입력에 일괄 CParagraphe 탐색을 적용하지 않는다. 새 입력의 같은 누락을 해결했다고 주장하지 않는다.
- **안정화**: 입력·결과 상한/child timeout은 무한 대기를 제한한다. CPU/메모리 OS sandbox나 모든 손상 입력의 정확한 처리를 증명하지 않는다. 008 Guard의 전체 Suite 역사적17+추가4 실패와009는 별도다.

새 Archive 구조를 추측해 읽기 범위를 넓히는 대신, 위 진입/map 및 전체 Serialize 종료의 새로운 독립 근거가 확보돼야 한다. 같은 002/003 정적 조사를 반복하거나 새 실기·디버깅·캡처를 자동 시작하지 않고 종료한다. 추가 TypeEdit 시험은 별도 승인 범위다.
